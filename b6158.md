## What and why

Fixes #6038. A client mod can add a chat line (`chat_line`) but nothing names the line afterwards, so a status message a mod repeats (Blood Magic's divination sigil reports an altar's or a soul network's numbers on every use) stacks up in the chat.

The fix adds two client host methods, keyed by a tag the mod chooses and scoped to the calling mod (`crash::current_native_mod`), so one mod can never touch another's lines:

- `NetworkClientHost::chat_line_tagged(tag, line) -> Result<(), TextFormError>`: when the calling mod already has a line under `tag` in the chat, its text becomes `line` in place (it keeps its position among the messages, counts as new for the HUD fade, and the wrapped lines are rebuilt as `ChatComponent.refreshTrimmedMessages` does). Otherwise the line is added exactly as `chat_line` adds it. To move the status line to the bottom a mod calls `chat_remove_tagged` first. Outside a mod's call it is `chat_line`.
- `NetworkClientHost::chat_remove_tagged(tag) -> usize`: removes the calling mod's lines under `tag` from the chat and its history and rewraps; returns how many went (0 for none). Lines added with `chat_line` and other mods' lines are never removed.

A replacement behaves as a new message does where that is observable: it is logged as `[CHAT]` and counted for the control socket (`remote.chat`, `chat_received`, `Chat::received`), and a reader scrolled up keeps the line they were on when the text wraps to more or fewer lines (a focused, scrolled chat also notes a new message, as `addMessageToDisplayQueue` does). The Chat option never hides this line (`ChatAbilities::shows` lets the client's own lines through).

Implementation: `Chat` (`sunrise-client-render/src/chat.rs`) gives a message an optional `(owner, key)`; `replace_keyed`, `remove_keyed`, and `set_next_key`/`clear_next_key` (the add path marks the next message it stores, so a message the Chat option hides is never marked). Compact chat never merges a keyed line with an equal one, so a replacement cannot change another message's repeat count. A line that left the history (the cap, a clear) is simply not found, so the next call adds a new one.

## Layer

## Vanilla reference

`ChatComponent.addMessage(Component, MessageSignature, GuiMessageTag)`, `ChatComponent.deleteMessage(MessageSignature)` and `refreshTrimmedMessages`. Vanilla names lines by signature and greys a deleted signed message out; a mod's own line has no signature, so it is replaced or removed outright. NeoForge has no event for this; mods call `ChatComponent` directly (Blood Magic's `ChatUtil.sendNoSpam`).
