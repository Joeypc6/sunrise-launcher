## What and why

Fixes #6173. A world draw could only submit text as `WorldDrawContext::name_tag`: always a camera-facing billboard 0.5 above a point, with no roll, tilt or fixed facing, and no glow or outline. Java mods draw text in `RenderLevelStageEvent` under a `PoseStack` they translate, rotate and scale freely, then call `Font.drawInBatch` (or `Font.drawInBatch8xOutline` for glowing sign style). `BlockEntityDrawContext::text` already draws posed, glowing and outlined text, but only from a block entity's renderer.

The fix gives `WorldDrawContext` the block entity's posed text, at a world position:

```rust
fn text(&mut self, origin: [f64; 3], pose: [f32; 12], text: &Text, options: WorldTextOptions) -> Result<f32, DrawError>;
fn text_width(&self, text: &Text) -> f32;
```

- `pose` is a row-major 3x4 local transform, the same form as `ModelInstance::transform`, placed at `origin` with the camera subtracted in `f64`. The line lies in the pose's x-y plane, one unit per font pixel, y down, read from +z, as `BlockEntityDrawContext::text` draws it. A camera-facing line with a roll is the camera rotation (`WorldRenderView::camera_rotation`) times the mod's own roll.
- `WorldTextOptions` (`#[non_exhaustive]`, `Default`, `with_*` builders) holds `Font.drawInBatch`'s arguments: `at`, `color` (ARGB), `shadow`, `background` (ARGB backdrop, none at alpha 0), `light`, and `see_through` (`DisplayMode.SEE_THROUGH`). It also holds `glowing` (full bright, as glowing sign text) and `outline` (ARGB, the eight ringed copies of `drawInBatch8xOutline`). The default is white text in full sky light, depth tested.
- Depth-tested text draws with the labels the world's name tags draw with, sorted far to near by `origin`. See-through text is drawn unlit with the labels' copies over everything. It returns the width drawn (`Font.width`, rounded up). `text_width` measures a line so it can be centred.
- A non-finite `origin`, `pose` or `at` is refused with the existing `DrawError::NonFinite`, and nothing is drawn. A scale is part of the pose matrix, so a NaN scale is refused this way too.
- One glyph path: the layout, the outline rings and the `TEXT_OVER_OUTLINE` lift move out of `native_draw_text` into a shared `Game::world_text_quads`. The block entity's `text` and the new world `text` both call it. The block entity output is unchanged: no shadow, no backdrop, the same light and pose. `native_draw_text_width` becomes `native_styled_text_width` and is shared by both `text_width`s.

  - `posed_text_turns_and_rolls_as_its_pose_says_and_non_finite_is_refused`: a 90° yaw, a 30° roll and both together move every vertex about the origin exactly as the matrix turns the unturned line. Non-finite origins, poses and starts are refused and draw nothing.
  - `glowing_text_is_full_bright_and_see_through_text_is_unlit_over_everything`: glowing puts full-bright light on every vertex and changes nothing else. See-through draws the same glyphs unlit in the see-through list.

The first eight copies are in the outline colour, each one font pixel round the glyph in `drawInBatch8xOutline`'s order, then the white text in front. A backdrop is one quad, first and just behind the glyphs.

## Kind

- [x] feature: label `feature` (mods get a new draw call)

## Layer

Mod API (`sunrise-mod-vocab`, client side) and its game implementation in `sunrise-client`. No wire type: `WorldTextOptions` is client-local, like `NameTagOptions`. No hot path: it costs nothing unless a mod calls it.

## Vanilla reference

- `Font.drawInBatch(Component, x, y, color, shadow, Matrix4f, MultiBufferSource, DisplayMode, backgroundColor, packedLight)`, with `PreparedTextBuilder.markBackground` for the backdrop and `DisplayMode.SEE_THROUGH` (`RenderPipelines.TEXT_SEE_THROUGH`).
- `Font.drawInBatch8xOutline`, which glowing sign text uses (`SignRenderer` / `AbstractSignRenderer`, with full-bright `LightCoordsUtil.FULL_BRIGHT`).
- NeoForge `RenderLevelStageEvent`: `getPoseStack()` translated, rotated (`Axis.ZP.rotationDegrees`) and scaled before `Font.drawInBatch`.
