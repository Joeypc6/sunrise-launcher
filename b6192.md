## What and why

Fixes #6143. `WorldDrawContext::name_tag` draws a mod's world label exactly at a name tag's size. A mod showing world text (Sunny Lyrics' lyric lines over a jukebox) can't make it larger or smaller.

This adds:
- `NameTagOptions::scale: f32`, the world size of one text pixel. The label is drawn under `PoseStack.scale(scale, -scale, scale)` where vanilla's name tag uses `0.025`, and it still sits 0.5 above `at`.
- `NameTagOptions::NAME_TAG_SCALE = 0.025`, the default from `NameTagOptions::new` and `Default`, so existing labels draw exactly as before.
- `NameTagOptions::with_scale(scale)`.
- `DrawError::InvalidScale`: a scale that is not finite, zero or negative refuses the label, and nothing is drawn. A finite scale so large that the text's camera-relative positions overflow f32 (`f32::MAX`) is refused with `DrawError::NonFinite`, as every other draw refuses an overflowing coordinate.
- The backdrop's layer gap behind the text (0.002 at a name tag's unit) scales with `scale / 0.025`, as vanilla's text-space gap is multiplied by the pose scale, so a scaled label is a scaled copy of the default one; real name tags (ratio exactly 1) draw byte for byte as before.
- `NameTagOptions` keeps `PartialEq` and `Eq` (the scale compares by its bits; both sides are destructured whole, so a later field must be compared too), and its `Default` is written out so the default scale is 0.025.

Files:
- `crates/sunrise-mod-vocab/src/client/world_draw.rs`: the field, constant, builder and error variant.
- `crates/sunrise-client/src/game/modding/native_custom_geometry.rs`: the label's text unit is `options.scale` (real name tags keep `NAME_TAG_UNIT`), the refusals, and the overflow check on the finished positions.
- `crates/sunrise-client/src/game/interface/names.rs`: `styled_name_tag_quads` scales the backdrop's gap with the unit.
- Docs: `WorldDrawContext::name_tag` (`host/draw.rs`), the `submit_custom_geometry` hook notes and `docs/modding/src/how-to/client/field-of-view-and-name-tags.md` (the `scale` row, the size sentence and the refusals).
- `crates/sunrise-client/src/game/modding/world_name_tag_tests.rs`: daily test `a_labels_scale_sizes_its_text_and_the_default_is_a_name_tags`, run in a fresh child process (`run_fresh_cases`), since the prepared game publishes process-wide tables. For every `see_through` x `background` combination, in both depth copies: the default and an explicit 0.025 draw byte for byte the same, and with 0.05 every vertex, the backdrop's included, lies twice as far from the anchor. 0, negative, NaN and infinite scales are refused with `InvalidScale` and `f32::MAX` with `NonFinite`, drawing nothing. Its row in `tools/ci/ignored-tests/world-name-tags.txt` is `child-process`. It reads no pixels.
- `crates/sunrise-mod-vocab/changes/name-tag-scale.toml`.
