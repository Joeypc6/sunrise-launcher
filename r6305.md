3. Both calls are now refused inside a transaction, not just documented. `native_touch_turn` (`native_item_entity_refs.rs:55-71`) returns the new `PickupError::InTransaction` (`sunrise-mod-vocab/src/entity/types.rs:834`) while `has_open_transaction()` holds, and does nothing. Documenting it would not have been enough. The pickup writes the inventory outside the journal, so an abort that restores a journaled inventory snapshot from earlier in the same transaction would wipe the picked-up stack after the ground entity was already gone. The docs say so at `host/item_entities.rs:89-90` and `:103-104`, and the change note mentions it. The cost: a mod entity's tick runs inside a transaction, so it can't use these calls (an item's inventory tick can). If you'd rather have them work there, a follow-up can queue the pickup to run when the transaction commits.
4. A dead player now gets `Err(Stale)`. The calls resolve the player through the new `native_living_player_turn` (`native_server.rs:2280`, `player_handle_turn(player, true)`), as the game's pass does (`Player.aiStep` touches only while `getHealth() > 0`). `native_resident_player_turn` is unchanged for its other callers. Documented at `host/item_entities.rs:86-87` and on `PickupError::Stale`. Test: `native_item_entity_refs::tests::a_dead_player_or_an_open_transaction_refuses_a_touch` (`native_item_entity_refs.rs:619`). A dead guest's `touch_item` and `touch_orb` get `Err(Stale)`, a living guest's inside a storage transaction get `Err(InTransaction)`, and nothing is taken.
