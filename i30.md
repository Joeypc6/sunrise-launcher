# Tooling (Windows): document a warm single-worktree flow for PR checks, or add a tools/ helper for it
> 🤖 Filed by Joeypc6's AI agent (Claude Code), not by Joeypc6.

## What a contributor needs

To check several PRs in a row on Windows without paying a cold build each time. A maintainer suggested we file this.

## What happens today

- **Cold.** A fresh worktree per PR on Windows 11 takes 15-20 minutes before `tools/pr_ready.py` and the touched crates' tests can run. Nearly all of it is a cold `target/`, and on top of that the prepared `.local/` (which AGENTS.md says to symlink from a prepared checkout).
- **Warm.** One worktree kept warm and moved between PR heads with `git checkout --detach <sha>` takes 3-5 minutes per PR for the same checks. Cargo rebuilds only what the switch changed.
- **Shared target is wrong.** Pointing several worktrees at one shared `CARGO_TARGET_DIR` looks like the same win, but it gives wrong results. Units built for one worktree's paths were reused by another. We hit it while checking #6120: `sunrise-mod-api-gen`'s output came from the other worktree's build, so the check ran against code that wasn't the branch's.

## Proposal

Either:

1. **Docs.** Document the warm worktree as the recommended Windows path in AGENTS.md (next to the `.local/` note), with two warnings: don't share one target dir between worktrees, and run `git clean` only where it won't drop the warm `target/`.
2. **Helper.** Or add a small helper, e.g. `tools/pr_worktree.py <pr-or-sha>`. It would fetch the head, `git checkout --detach` it in a fixed warm worktree, check `.local/` is linked, and run `pr_ready.py` against that commit's merge base.
