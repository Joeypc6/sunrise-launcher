## What a mod needs

A spawner modifier that ignores light: the spawner's mob spawns whatever the block and sky light are, but every other part of its placement rule still applies (solid ground, the dimension, a hostile mob in Peaceful). Apothic Spawners' "Ignore Light" does this in Java. `SpawnerLogicExt` runs vanilla's `SpawnPlacements.checkSpawnRules` against a `LyingLevel`, a level wrapper that answers every light read with a passing value, so the type's own predicate decides everything except light.

## What happens on main (2bf35a4c42)

- `LevelRef::check_spawn_rules(host, kind, pos, reason, LightOverride::Any)` (#6042 / #6259) is that query. It returns `Err(Unavailable)` "while the engine holds the level random out of the level for its own pass (natural spawning, a spawner's or trial spawner's tick ...)" and for a call from inside a `mob_spawn_placement_check` listener (`host/level_spawning.rs`).
- A spawner's placement check runs inside the spawner's tick, and that's the only place the modifier can act: the spawner tick fires `mob_spawn_placement_check` with `default_result` already computed against real light. So a spawner can never use the override for its own spawns.
- The listener sees `default_result` and the shared `random`, but it can't ask what the predicate would answer under other light. Setting `result = Succeed` skips the whole rule, not just its light part: a spider spawner would then also spawn on air or glass. That's wider than Java's behaviour.

## Proposal

Let the listener re-run the predicate itself on the stream it already holds, rather than on a copy of the level random:

```rust
// On the mob_spawn_placement_check event:
/// The effective placement predicate for this check (`default_result`'s predicate, registered
/// replacements included) evaluated again with `light` supplied for sky and block light, as
/// `check_spawn_rules`' override does. Draws from this event's `random`, as vanilla's predicate
/// draws from the caller's `RandomSource`. The hook isn't re-entered. `Any` tries 0 to 15 and
/// stops at the first pass.
fn predicate_with_light(&mut self, light: LightOverride) -> bool;
```

A listener then writes `result = if event.predicate_with_light(LightOverride::Any) { Succeed } else { Fail }` for spawns it owns. The re-entrancy and level-random rules on `check_spawn_rules` stay as they are.

Second part: which spawner is asking. The placement check has no spawner field (like NeoForge's `SpawnPlacementCheck`), but a modifier belongs to one spawner. Today a mod can only guess: `reason == Spawner`, then the nearest modified spawner whose spawn box holds `pos`. When two modified spawners' boxes overlap, one spawner can borrow the other's flags. `mob_spawn_position_check` already carries `spawner: Option<Spawner>` (`Spawner::Block { pos }` / `Spawner::Minecart { entity }`). Please add the same field to `mob_spawn_placement_check`. A documented order (placement check, then position check, inside one spawner tick) would be a weaker fallback.

## Vanilla / NeoForge reference

- `BaseSpawner.serverTick`: `SpawnPlacements.checkSpawnRules(type, level, EntitySpawnReason.SPAWNER, pos, random)` with the spawner's level and random.
- `SpawnPlacements.checkSpawnRules` → `SpawnPredicate.test(type, level, reason, pos, random)`; `Monster.checkMonsterSpawnRules` reads `isDarkEnoughToSpawn` (sky and block light).
- NeoForge: `MobSpawnEvent.SpawnPlacementCheck` (no spawner), `MobSpawnEvent.PositionCheck.getSpawner()`.
