Thanks for the review. Before I rework this, one question, because point 1 and the issue this PR fixes pull in opposite directions.

- #5786 (the issue) lists `mod_pipeline_slot` among the settings to wire: "routing a custom `RenderSetup`'s registered mod render pipeline into the item/entity draw path", and "Wire each of these into the draw paths that consume `RenderTypeRef`".
- Point 1 of the review: "Special items are meant to keep translucency, layering and UV offset only, with the custom `RenderSetup` pipeline slot removed (#5992)" and "Remove the partial route".
- #5992 is still open and says the choice between wiring the textures and pipeline slot at every draw, or removing the fields, "is still to be decided".

Vanilla 26.3 settles what a full route means. `RenderType.draw` sets `RenderSetup.pipeline` on the pass and binds `RenderSetup.textures` by name, `Sampler2` only with `useLightmap`. A pipeline route without those bindings, without the item display's sort/OIT path, and with a run that can be skipped (point 2) is not vanilla. I agree it should not ship as it is.

Proposal:
1. In this PR, drop the pipeline route (`ItemQuad::mod_pipeline`, `PipelineRouting`, `submit_item_pipeline_quads`) and leave the slot for #5992. The PR becomes "Part of #5786" and says that pipeline routing waits on #5992.
2. Rework the other three settings #5786 asks for along points 2 to 7:
   - `use_lightmap(false)` leaves the lightmap unbound and unsampled, not max packed light.
   - `IsOutline` / `AffectsOutline` follow `RenderType.outline()` and the selected mask. No silhouette is drawn when the binding is absent.
   - The glint matrix is applied in the glint texture's own UV space, not to packed atlas UVs.
   - An unhandled `TextureTransform` variant no longer counts as identity.
   - Tests check the exact submitted output.
   - The change note is narrative.
3. If #5992 decides to wire the bindings, the pipeline route follows there, done in full: textures, lightmap, validation, and the same sort/OIT path.

Is that the direction you want, or should #5786's pipeline item be dropped from the issue itself?
