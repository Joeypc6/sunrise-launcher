Changes are in 5265cd411d.

1. Tiling now loops over integer row and column indices, and each tile's corner is `left + column * tw` / `top + row * th`, with the width and height clamped to `[0, tile]` (`crates/sunrise-client/src/game/host/draw/gui_canvas.rs:206`). The tile count is computed in `f64`. Regression: `a_far_off_or_huge_fluid_rectangle_ends_after_its_tiles` (`gui_canvas.rs:1468`) draws `[536870912.0, 0.0, 64.0, 16.0]` and expects four quads (24 vertices).
2. The sprite comes from `HudAtlas::texture_rect` (`gui_canvas.rs:184`), so `minecraft:block/water_still` finds the packed `block/water_still`. The GUI lookup and the `sprites.get(name)` fallback are gone, and a registered atlas's sprite binds its page. Every new test inserts its sprites only into `atlas.sprites`. `vanilla_water_and_lava_draw_their_block_still_sprites_as_an_items_fluid_layer_does` (`gui_canvas.rs:1387`) goes through `canvas.fluid`. `a_declared_fluid_tiles_its_looks_sprite_from_the_top_left_and_cuts_the_last_tiles` (`gui_canvas.rs:1416`) draws a declared look naming `a:block/oil`, packed as a model-atlas sprite.
3. `fluid()` now reads `fluid_models::item_appearance` (`gui_canvas.rs:558`). A fluid no model knows draws the missing sprite untinted, as the item resolver does, and `minecraft:empty` draws nothing. The guessed `<ns>:block/<path>_still`, the grey and water fallbacks, the flat fill and the look-alpha passthrough are removed, and `native_panel_recipes::fluid_tint` is `pub(super)` again. To give the canvas a look's appearance without touching globals, `item_appearance`'s per-look rule is factored out as `fluid_models::look_appearance` (`crates/sunrise-client-render/src/fluid_models.rs:216`). The index build calls it for world and tank looks alike, so behaviour is unchanged. The declared-fluid test checks the opaque-alpha rule (`0x00112233` draws `0xFF112233`), white for a sprite with no tint, and a registered model's still sprite winning.
4. No test calls `set_fluid_looks` any more, and `with_water_look` is removed. The vanilla tests read `item_appearance("minecraft:water" / "minecraft:lava")`, which comes from `block_sprites::fluid_faces`. Every `reindex` rewrites that table identically under the write lock, so another test's looks cannot change it. The declared-fluid and missing-sprite tests give the canvas the appearance directly through `GameGuiCanvas::paint_fluid` (`gui_canvas.rs:180`), so they need no child process and no daily row.
5. The stretch past the cap stays, and its value is now explained (`gui_canvas.rs:263`). Index-based tiling ends, but not in bounded time. `rect_end` accepts any finite `f32` rect, so `[0, 0, 1e30, 1e30]` would still mean about 4e57 iterations of appended vertices. The doc says vanilla 26.3 has no GUI fluid draw, and that JEI's `drawTiledSprite` counts tiles in `int` GUI pixels, so a screen bounds JEI. 4096 is Sunrise's own per-call bound: 4096 tiles of 16 px cover 1024 x 1024 GUI pixels, more than a 3840 x 2160 screen at GUI scale 3 (1280 x 720). The same test checks that `[0, 0, 1e30, 16]` draws one quad.

Smaller: the stacked doc comment is gone, since the tests were rewritten. `docs/modding/src/how-to/client/gui-paint.md` now has a Fluids section, and Refusals lists `UnknownFluid`.

The public signature is unchanged: `fn fluid(&mut self, fluid: &FluidStack, rect: [f32; 4]) -> Result<(), GuiDrawError>`.
