## What and why

Fixes #6035. A mod cannot ask another block state for three answers that vanilla blocks give: how much light it stops, whether an entity inside it suffocates, and whether a mob may spawn on top of it. Applied Energistics 2's cable bus needs the light dampening of a state and falls back to vanilla's default rule. Elevator is camouflaged as another block and answers suffocation and spawning with the held state's answers; its port works them out from shapes and a list of see-through blocks.

What the commit adds, on `BlockStates` (both sides, state alone, no position):
- `light_block(state) -> Option<u8>`: `BlockState.getLightBlock()`, 0 to 15 (stone 15, water and leaves 1, glass and air 0). Read from the exported per-state facts.
- `is_suffocating(state) -> Option<bool>`: the block's own `isSuffocating` predicate from the game's suffocation rules. `None` when the answer needs a position or a block entity: a closed shulker box, or a shape a block entity publishes or an offset moves. New `SuffocationRegistry::constant(state)` gives the constant answers.
- `is_valid_spawn(state, entity_type) -> Option<bool>`: `BlockState.isValidSpawn` from the table natural spawning reads. Leaves admit ocelots and parrots, ice polar bears, magma blocks only fire immune types, and a block's declared spawn rule is already in the flags. `None` for an entity type with no spawn species. Natural spawning's surface check is split into `spawn_state_valid`, and `spawn_rules::is_valid_spawn_on` is the new public entry.
- All three return `None` for an unknown state, as the other reads in `BlockStates` do.

And the position-dependent case, on `LevelRef` (both sides):
- `state_is_suffocating(host, pos, state) -> Option<bool>`: `BlockState.isSuffocating(level, pos)` for a supplied state at a position, which need not be the block stored there, so a camouflaged block asks about the state it shows. It runs the same suffocation rules entities use (`SuffocationRegistry::is_suffocating` over the level's block entities): a shulker box suffocates unless the `ShulkerBoxBlockEntity` at `pos` is not closed, no block entity there counting as closed (`Blocks.shulkerBox`'s predicate); a published or offset shape is tested at `pos`. Reads active and parked server levels and the client's current level, never loads chunks; `None` for an unloaded or out-of-height position, a stale level and an unknown state.
- `is_valid_spawn` needs no level read: the game's natural spawning decides `isValidSpawn` from the state's flags alone, so the state read holds at every position. Its docs now name vanilla's default rule (`BlockBehaviour.Properties.isValidSpawn`: a sturdy top face and light emission below 14).

## Vanilla reference

- `BlockBehaviour.BlockStateBase.getLightBlock`, `isSuffocating`, `isValidSpawn`
- `Blocks.shulkerBox`: the `isSuffocating` predicate that reads the `ShulkerBoxBlockEntity` at the position (`isClosed`), true when there is none
- `BlockBehaviour.Properties.isSuffocating` and `isValidSpawn`
- The spawn rules for leaves (ocelot, parrot), ice (polar bear) and magma (fire immune) in `SpawnPlacements`
- NeoForge: no extra hook; mods call these on any state.
