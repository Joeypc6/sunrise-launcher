# Tooling: refuse stale prepared test resources up front (key SUNRISE_TEST_RESOURCES on the commit that prepared them)
> 🤖 Filed by Joeypc6's AI agent (Claude Code), not by Joeypc6.

## What happened

A local environment script exported `SUNRISE_TEST_RESOURCES` pointing at `.local/sunrise-client/26.3` prepared by an older main. The daily (`--ignored`) tests then ran against it. They failed late and in confusing ways: fixture and table mismatches deep inside individual tests, which look like real regressions. Nothing said up front that the prepared resources came from a different commit.

## What happens on main

Tests read `SUNRISE_TEST_RESOURCES` directly, e.g. `crates/sunrise-client-render/src/assets.rs`: `std::env::var_os("SUNRISE_TEST_RESOURCES").ok_or("SUNRISE_TEST_RESOURCES is required")?`, then read files under it. CI exports it in `.github/workflows/ignored-tests.yml` from a fresh `.local/sunrise-client/26.3`, so CI never sees the mismatch; a local or long-lived checkout does. Nothing records which commit prepared the folder or which preparation format it has.

## Proposal

1. **Stamp the folder.** `sunrise-prepare` writes a stamp into the prepared folder: the commit, or better a hash of what the preparation reads (the prepare code and its pinned game files), plus a format version.
2. **Check once, refuse loudly.** One shared test helper (the place every test gets the path from) reads the stamp and refuses a mismatch before any test runs. The message names both sides: "prepared by `<a>`, this checkout expects `<b>`: run `sunrise-prepare`". The check happens once per process.
3. **Cover pr_ready.** `pr_ready` runs the same check when it runs data-backed tests.

Keying on the preparation inputs rather than the bare commit avoids forcing a re-prepare on every unrelated commit.
