## What and why

Fixes #6042. A mod cannot run an entity type's spawn rules at a position with the light check overridden. Apothic Spawners' "Ignore Light" modifier lets a spawner spawn mobs whose rules want darkness or daylight at any light. Java retries `SpawnPlacements.checkSpawnRules` through a level wrapper that reports every light level. The Sunrise port only sees the predicate's answer at the real light and guesses. Ender IO's powered spawner also needs a mod spawner to ask other mods' spawn checks.

What the commit adds:
- `LevelRef::check_spawn_rules(host, kind, pos, reason, light) -> Result<bool, LevelReadError>` (backend `level_check_spawn_rules`), server only.
- It runs the type's registered placement predicate (vanilla's, or one from `register_spawn_placement`) with the light reads the `LightOverride` names, then the `mob_spawn_placement_check` hook as natural spawning asks it, so other mods' spawn checks apply. `reason` is passed to the rule and the hook.
- Any entity type, as spawners check one (`SpawnerTypeFacts::placement_type`): a type with no placement entry, a non-mob included, passes its vanilla rule as in `SpawnPlacements.checkSpawnRules`, and registered predicates and the hook still answer for it.
- New `LightOverride { Real, Level(u8), Any }`. `Real` reads the level's light. `Level(n)` makes sky and block light both read `n` (more than 15 is 15) at every position the rule reads. `Any` tries 0 up to 15 until one passes; the hook runs once per level tried.
- The override reaches the predicate and `default_result`. The hook's `level` handle still reads the real light (NeoForge's event would carry the wrapped level); documented and tested.
- Random contract: the predicate and the hook draw from one copy of the level random (`LevelRandom`), never written back. The level's stream does not move, two calls at an unchanged state draw the same rolls, and each `Any` try draws after the one before.
- The level is built once per call; `Any` tries every light on it.
- `Ok(false)` for an unloaded position and an id that names no entity type. `Err(Stale)` for a stale handle. `Err(Unavailable)` on a client, for a level not in place, for a light override this build does not know, and for a call made while another runs on the thread (a listener asking again), so a listener cannot recurse.
- The `mob_spawn_placement_check` docs and notes and the book's "Spawning from a level" name the new caller.
- In `sunrise-client`: `FixedLight<L>` wraps a `SpawnLevel` and overrides only sky and block light. `Game::check_spawn_rules_with_light` holds the shared logic.
