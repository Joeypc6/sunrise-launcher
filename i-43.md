## What happens

A content mod with one item and 45,000 recipe files of vanilla types over vanilla item ids (18k `crafting_shaped`, 18k `crafting_shapeless`, 9k `smelting` in `data/<mod>/recipe/`) changes a single-player Windows client like this, compared with no mod:

| | no mod | 45k recipes | delta |
|---|---|---|---|
| resident at the title (`memory` → `process.resident_mb`) | 826 MiB | 1,536 MiB | **+710 MiB** |
| resident in world | 1,528 MiB | 3,077 MiB | **+1,550 MiB** |
| allocator commit, title / world | 1,792 / 3,826 MiB | 1,865 / 3,628 MiB | +73 / −198 MiB |
| `unattributed_mb`, title / world | | | **+710 / +1,550 MiB** |
| title → world loaded | 4.8 s | 15.4 s | **+10.6 s** (trace: `server.open_world` 13.5 s) |
| start → title, warm | — | 41.3 s | last startup-trace span ends at 28.0 s: **~13 s untraced** |

Measured on main 70d397565a with one unrelated local patch, offscreen client, the same video options. Timings are ±30% (other builds ran on the machine). The memory numbers are stable across runs, and the same +1.4–1.5 GiB showed in an earlier run with 10k items + 50k recipes (there the untraced gap was ~40 s).

## Points to look at

1. **The memory isn't on the Rust heap.** Allocator commit barely moves, and every extra MiB lands in the memory report's `unattributed_mb`. So it is resident memory outside the allocator: file-backed or mapped pages kept from reading the package's 45k entries, a C-library allocation, or something similar. ~35 KiB resident per recipe in world (~16 KiB at the title) is far above what a parsed recipe needs.
2. **World join grows by ~10 s.** `server.open_world` is 13.5 s with the recipes, and the world rebinds or reparses them. `rest.recipe_sources` is 4.9–5.1 s at startup on its own.
3. **Startup has a gap no span covers.** After the last `SUNRISE_STARTUP_TRACE` span, ~13 s pass before the title (40 s at 50k recipes), so the trace can't say where the time goes. A span around whatever runs there would make it measurable.

Recipe counts like this are normal for large modpacks: big packs ship tens of thousands of recipes, much of it generated data.

## Repro

1. Generate a content mod: one item, plus 45,000 recipe JSON files in `data/<mod>/recipe/` (shaped, shapeless and smelting, with ingredients and results drawn from vanilla items).
2. Start the client to the title, read `memory` (`process.resident_mb`, `allocator`, `unattributed_mb`), open a new world, and read it again. Then repeat with no mod.
3. Compare `SUNRISE_STARTUP_TRACE` output: the last span's end against the time the title appears, and `server.open_world`.

Startup traces and client join profiles are available on request.
