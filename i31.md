# Tooling: pr_ready tests the touched crates and their dependents, never the whole suite; the full suite runs once in CI
> 🤖 Filed by Joeypc6's AI agent (Claude Code), not by Joeypc6.

## What we'd like

A local `pr_ready` run tests what a diff can break: the crates it touches and the crates that depend on them. The full workspace suite runs once, in CI. A maintainer told us this is already the rule, so this asks for `pr_ready` to enforce it rather than for a new policy.

## What happens on main (tools/pr_ready.py)

- **Tests.** They run for `touched_crates(changed, ...)` only, not their dependents. A change to a library crate can therefore pass locally and fail in a dependent's tests in CI.
  - In the other direction, an unrecognised Rust path makes `crates = None`, and the run falls back to `--workspace`: the whole suite, locally. On a Windows host that's the slow case.
- **Clippy.** It already widens to `dependent_crates(...)`, then runs CI's workspace-wide command.

## Proposal

1. **Dependents.** Test the touched crates plus `dependent_crates(...)`, the set clippy already computes, with the features CI gives them.
2. **No silent fallback.** Replace the `--workspace` fallback for an unrecognised Rust path with a refusal that names the path, so it gets mapped, or with an explicit `--full` flag. A local run then never starts the full suite unasked.
3. **Report it.** Print the crate set and why each crate is in it ("touched", "depends on X"), so a reviewer can see what was covered.
